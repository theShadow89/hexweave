## Hexweave repo brief

Parametric HSW panel generator. Next.js 16 App Router + React 19 + Three.js via react-three-fiber, TypeScript strict, npm.

### Invariants (do NOT change)

- `HSW_STANDARD` in `src/lib/hsw/constants.ts`: `cellInnerWidth=20`, `wallThickness=3.6`, `depth=8`, `orientation="flat"`. Every generated panel has to clip-fit the original RostaP HSW inserts (Printables model 152592).
- `DEFAULT_INSERT`, `DEFAULT_WALL_MOUNT` variant defaults.
- The `barbed_tab` polygon and geometry code in `src/lib/openscad/scad/library.ts` / `src/lib/openscad/scad/*.ts`. Regenerated by `scripts/extract-tab-polygon-v2.ts`; do not hand-edit.

### HswParams shape (current)

`{ cellInnerWidth: 20, wallThickness: 3.6, depth: 8, orientation: "flat", cellHoleExpansion: number }`

`cellHoleExpansion` is a user-facing knob (Material profile in the UI). Presets in `MATERIAL_PROFILES`:

- PETG = 0 mm (RostaP native, no compensation)
- PLA = +0.15 mm (typical PLA over-extrusion)
- ABS = -0.05 mm (post-cool contraction)
- custom = arbitrary value

Applied ONLY to the panel cell hole (front, rear, pocket). Insert geometry is never scaled by it. When panel and insert share the same material, leave at PETG.

### Insert / subdivision primitives

- **Vertical seam clusters**: 3-cell horizontal cluster (full + bisected + full) on uncrossed vertical seams.
- **Cross-cluster**: 6-cell insert at every X-junction; shape depends on column parity (odd = hourglass, even = hex ring).
- **Bridges**: 2-cell insert on horizontal seams, `AUTO_BRIDGE_SPACING_MM = 200`, formula `max(1, ceil(seamLength / 200))`.
- **Wall mounts**: countersunk M3 / M4 / M5, global count. Auto = `1` if longest side < 200 mm, else `max(2, ceil(longest / 400))`.
- **Merge mounts into clusters**: default on. Wall-mount cells snap onto cluster cells; the countersunk hole is folded into the cluster cell.

### Cell variants (9)

`empty`, `solid`, `hollow`, `m3`, `m4`, `m5`, `countersunk-m3`, `countersunk-m4`, `countersunk-m5`. Two global defaults (clip / mount), per-cell overrides via UI.

### Agent surface

Fully client-side (BYOK). No server routes, no env config: the user configures provider/model/key in-app and the LLM call runs directly from the browser/renderer.

- `src/lib/agent/tools.ts` — canonical tool catalog (typed by `AgentTool` in `types.ts`, not an SDK).
- `src/lib/agent/prompts.ts` — SHARED_RULES + per-mode system prompts.
- `src/lib/agent/runAgent.ts` — client-side provider call (Anthropic via direct-browser CORS, or OpenAI-compatible), normalised to `ContentBlock[]`.
- `src/lib/agent/config.ts` — non-secret config types + defaults; `configStore.ts` persists them in localStorage.
- `src/lib/agent/keystore.ts` — local secure key storage: OS keychain via `window.hexweave.keystore` (Electron `safeStorage`) on desktop, passphrase-encrypted (AES-GCM/PBKDF2) in localStorage on web.
- `src/components/Agent/AgentSettings.tsx` — in-app config UI; `AgentPanel.tsx` — chat/dispatch.
- `src/app/page.tsx` — `agentContext` (state snapshot) and `handleAgentTool` (dispatch). Every tool needs a matching `case` in `handleAgentTool`.
- Modes: `chat-config`, `optimizer`, `end-to-end`. Providers: `anthropic` or `openai_compatible`.
- Available when a provider/model is configured and a key is stored (and unlocked on web). Otherwise the panel shows a setup hint.
